# Login และสมัครสมาชิก (ชุดทดสอบรายวิชา)

เปิดแท็บโปรไฟล์ → บัญชีของฉัน → เข้าสู่ระบบ / สมัครสมาชิกใหม่

- `/signup` สมัครบัญชีด้วยชื่อ อีเมล รหัสผ่าน และยืนยันรหัสผ่าน
- `/login` เข้าสู่ระบบด้วยบัญชีที่สมัคร
- `/register?id=...` **ลงทะเบียนเข้าร่วมกิจกรรม** เป็นคนละหน้ากับสมัครสมาชิก และต้องเข้าสู่ระบบก่อน
- Token เก็บใน SecureStore; รหัสผ่านไม่เก็บในแอป
- API ตัวอย่าง hash รหัสผ่านด้วย scrypt และ salt แยกแต่ละบัญชี ตรวจอีเมลซ้ำและตรวจสิทธิ์ที่เซิร์ฟเวอร์

## เปิด API บน Windows CMD

ในโฟลเดอร์โปรเจกต์ เปิด CMD แรก กำหนดบัญชีสำหรับทดสอบเท่านั้น (แทนค่าของตัวเอง):

```bat
set "CAMPUS_TEST_EMAIL=student@example.test"
set "CAMPUS_TEST_PASSWORD=YOUR_DISPOSABLE_PASSWORD"
npm run api:mock
```

เปิด CMD อีกหน้าต่าง ใช้ `ipconfig` ดู IPv4 ของคอมพิวเตอร์ แล้วสร้างไฟล์ `.env` ในโปรเจกต์:

```dotenv
EXPO_PUBLIC_API_URL=http://YOUR_COMPUTER_LAN_IP:4100
```

แทน `YOUR_COMPUTER_LAN_IP` ด้วย IPv4 จริง โทรศัพท์กับคอมต้องอยู่ Wi-Fi เดียวกัน และ Windows Firewall ต้องอนุญาต Node บนเครือข่ายส่วนตัว จากนั้น:

```bat
npx expo start --go --lan -c
```

อย่าใช้ `localhost` บนโทรศัพท์ เพราะจะหมายถึงตัวโทรศัพท์เอง การตั้ง URL สำหรับ Metro/tunnel ไม่ได้เปิด API port 4100 ให้โดยอัตโนมัติ

หากไม่ได้ตั้ง API ยังดูสถานที่และใช้ฟีเจอร์ในเครื่องได้ แต่ปุ่มส่งข้อมูล Login/สมัครสมาชิกจะปิดพร้อมข้อความอธิบาย

## ขอบเขต

API นี้เป็น **local classroom API แบบเก็บข้อมูลถาวร** บัญชี ชื่อโปรไฟล์ session และรายการลงทะเบียนเก็บใน `.local-data/accounts.json` บนคอมพิวเตอร์ที่รัน API ใช้การเขียนไฟล์ชั่วคราวแล้วเปลี่ยนชื่อไฟล์ และไม่เก็บไฟล์นี้ใน Git ให้รัน API เพียงหนึ่ง process ต่อไฟล์ข้อมูล

- รีสตาร์ต API แล้วบัญชีเดิมยังใช้ได้ ไม่ต้องสมัครใหม่
- รหัสผ่านเก็บเป็น scrypt hash พร้อม salt; token บนเซิร์ฟเวอร์เก็บเฉพาะ SHA-256 digest
- Session อายุ 7 วัน เมื่อหมดอายุต้องเข้าสู่ระบบใหม่ ไม่มี automatic refresh ในชุดนี้
- Logout ลบ token ในโทรศัพท์ และเพิกถอน token บน API เมื่อเชื่อมต่อได้ หาก offline ฝั่งเซิร์ฟเวอร์จะหมดอายุตามกำหนด
- ตั้ง `CAMPUS_DATA_FILE` เพื่อเปลี่ยนตำแหน่งไฟล์ และ `CAMPUS_SESSION_TTL_MS` เพื่อจำลองหมดอายุในการทดสอบ (หน่วยมิลลิวินาที)
- สำรองไฟล์ข้อมูลไว้ในที่ส่วนตัว อย่าแชร์หรือ commit; หากไฟล์เสีย API จะหยุดเพื่อไม่เขียนทับข้อมูลเดิม
- เปลี่ยน `CAMPUS_TEST_PASSWORD` ไม่ได้เปลี่ยนรหัสผ่านของ seed account ที่บันทึกไว้แล้ว

## โปรไฟล์และข้อมูลส่วนตัว

แท็บโปรไฟล์แสดงบัญชีของผู้ใช้ แก้ชื่อได้ และมีทางเข้า My Trip/กิจกรรมที่บันทึก ส่วนประวัติและข้อมูลติดต่อผู้พัฒนาย้ายไป `/about` ผ่านปุ่ม “รู้จักผู้พัฒนาแอป”

My Trip, รายการโปรดกิจกรรม และกิจกรรมที่สร้างเองเก็บในโทรศัพท์แยกตาม user ID ยังไม่ซิงก์ข้ามเครื่อง และจะหายหากล้างข้อมูลแอป การออกจากระบบไม่ลบรายการเหล่านี้ กลับเข้าบัญชีเดิมบนเครื่องเดิมจะเห็นข้อมูลเดิม หน้าค้นหา แผนที่ รายละเอียดสถานที่ และกล้องยังเปิดได้โดยไม่ล็อกอิน; การบันทึกทริป/รายการโปรด/สร้างกิจกรรมจะชวนเข้าสู่ระบบ

รายการแบบไม่ผูกบัญชีจากรุ่นก่อนยังไม่ถูกลบ แต่ไม่ย้ายให้บัญชีแรกอัตโนมัติ เพราะไม่ทราบว่าเป็นของใคร รุ่นนี้เริ่มรายการส่วนตัวชุดใหม่หลังเข้าสู่ระบบ การแจ้งเตือนที่เคยตั้งไว้เป็นของอุปกรณ์และไม่ได้ย้ายหรือยกเลิกอัตโนมัติเมื่อเปลี่ยนบัญชี

ยังเป็นระบบสำหรับงานเรียนบนเครือข่ายส่วนตัว ไม่ใช่บริการ production: ไม่มี HTTPS hosting, email verification, password reset หรือ rate limiting ไม่ใช้รหัสผ่านจริงซ้ำกับบริการอื่น

## ตรวจด้วยตนเอง

1. เปิด API และแอป → โปรไฟล์ → สมัครสมาชิก
2. รหัสผ่านไม่ตรงกัน: แสดง error และไม่ส่งข้อมูล
3. สมัครสำเร็จ: ไปหน้ากิจกรรม และโปรไฟล์แสดงชื่อบัญชี
4. ออกจากระบบ → ลองรหัสผ่านผิด → แก้ข้อมูลแล้วเข้าสู่ระบบได้
5. รีสตาร์ต API และแอป → restore session ภายใน 7 วัน
6. อีเมลที่สมัครแล้ว → แสดง error พร้อมทางเข้า Login
7. เปิดกิจกรรมจาก API → ลงทะเบียนเข้าร่วม → ลองส่งซ้ำ ต้องไม่สร้างรายการซ้ำ

8. บัญชี A เพิ่มทริป/รายการโปรด/กิจกรรมส่วนตัว → logout → บัญชี B ต้องไม่เห็นข้อมูล A → กลับเข้า A ข้อมูลยังอยู่
9. แก้ชื่อในโปรไฟล์ → รีสตาร์ต API และแอป → ชื่อใหม่ยังอยู่
10. เปิด “รู้จักผู้พัฒนาแอป” → เห็นประวัติผู้พัฒนาแยกจากโปรไฟล์ผู้ใช้
11. ทดลอง token หมดอายุ → กลับเป็นผู้เยี่ยมชมและเข้าหน้าลงทะเบียนกิจกรรมที่ป้องกันไว้ไม่ได้
