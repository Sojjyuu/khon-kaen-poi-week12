# บัญชี โปรไฟล์ และบันทึกทริป

## เปิด API + Expo ด้วยคำสั่งเดียว

ใช้ Node.js 22.13 ขึ้นไป และ npm ในโฟลเดอร์ที่มี package.json:

```bat
npm ci
npm start -- --clear
```

`npm start` เปิด API ที่ port 4100 แล้วเปิด Expo Go แบบ LAN เมื่อ API พร้อม กด Ctrl+C เพื่อหยุดทั้งคู่ ไม่ต้องสร้าง seed account ก่อน สมัครผ่านแอปได้เลย หาก port ถูกใช้อยู่ให้หยุด API/Expo หน้าต่างเก่าก่อน

โทรศัพท์และคอมพิวเตอร์ต้องอยู่เครือข่ายเดียวกันและเข้าถึงกันได้ อนุญาต Node ผ่าน Firewall ตามเครือข่ายที่ใช้ เปิด `http://<IP-Wi-Fi-คอม>:4100/health` บนโทรศัพท์แล้วต้องเห็น `{"ok":true}`

แอป development อ่าน IP จาก Expo LAN อัตโนมัติ หาก `.env` เดิมมี `EXPO_PUBLIC_API_URL` จะใช้ค่านั้นก่อน: ลบบรรทัดเก่าหากต้องการโหมดอัตโนมัติ หรือแก้ให้ตรงกับ IP ปัจจุบัน แล้วเริ่มใหม่ด้วย `npm start -- --clear` ไม่ใช้ IP ของ Radmin VPN และไม่ใช้ localhost บนโทรศัพท์จริง

หากใช้ Expo tunnel หรือ Preview/Production Build ต้องกำหนด URL ของ API ที่มือถือเข้าถึงได้เอง; tunnel ของ Expo ไม่ได้เปิด API port 4100 ให้อัตโนมัติ การเริ่มด้วย `npm run start:expo` เปิดเฉพาะ Expo และ `npm run api:mock` เปิดเฉพาะ API

## ข้อมูลบัญชีและ SQLite

- `/signup` สมัครสมาชิก; `/login` เข้าสู่ระบบ; `/register?id=...` ลงทะเบียนกิจกรรม เป็นคนละฟีเจอร์
- แก้ SecureStore key เป็น `khonkaen.session-token` เพราะ `/` ใน key เดิมใช้บนอุปกรณ์จริงไม่ได้
- SQLite อยู่ที่ `.local-data/accounts.sqlite` บนเครื่อง API เก็บบัญชี โปรไฟล์ session การลงทะเบียน และบันทึกทริป
- เปิดครั้งแรกจะย้ายบัญชีจาก `.local-data/accounts.json` เดิมโดยคง user ID/hash/session และไม่ลบไฟล์เดิม; ไฟล์เสียจะหยุดเพื่อให้แก้ ไม่เขียนทับเงียบ ๆ
- รหัสผ่านเก็บ scrypt hash พร้อม salt; token ฝั่ง API เก็บ SHA-256 digest ส่วนแอปเก็บ token ใน SecureStore
- Session อายุ 7 วัน ไม่มี automatic refresh; logout ลบ token ในเครื่องและเพิกถอนบน API เมื่อเชื่อมต่อได้
- ใช้ API หนึ่ง process ต่อฐานข้อมูล สำรองข้อมูลเมื่อหยุด API แล้ว ไม่แชร์ฐานข้อมูลหรือ commit เข้า Git
- เปลี่ยนตำแหน่งด้วย `CAMPUS_DATABASE_FILE`; `CAMPUS_DATA_FILE` ระบุ JSON สำหรับ migration และใช้อนุมานชื่อ SQLite หากไม่ได้ตั้ง database path
- Seed account เป็นทางเลือก: ตั้งทั้ง `CAMPUS_TEST_EMAIL` และ `CAMPUS_TEST_PASSWORD` หรือไม่ตั้งทั้งคู่ ค่ารหัสผ่านนี้ไม่เปลี่ยนบัญชีเดิมที่มีแล้ว

## โปรไฟล์และทริป

โปรไฟล์ผู้ใช้แก้ชื่อ รูป และแนะนำตัวได้ ส่วนผู้พัฒนาอยู่หน้า `/about` แยกกัน รูปโปรไฟล์รองรับ JPEG/PNG สูงสุด 500 KB เลือกภาพแล้วกดบันทึกโปรไฟล์

My Trip เดิมคือรายการสถานที่ที่อยากไป มีปุ่ม “บันทึกการเดินทางของฉัน” ไปยัง `/journeys` สร้าง/แก้/ลบบันทึกที่มีชื่อ วันเดินทาง (ค.ศ. YYYY-MM-DD) โน้ต รูป JPEG/PNG สูงสุด 2 MB และสถานที่หลายแห่ง เริ่มเลือกจาก My Trip เดิมให้โดยอัตโนมัติ

บันทึกการเดินทางและโปรไฟล์อยู่บน API จึงเห็นบนอุปกรณ์อื่นเมื่อเข้าบัญชีเดิมและใช้ API/ฐานข้อมูลเดียวกัน ต้องเปิด API และเชื่อมต่อได้ในการโหลดหรือบันทึก ยังไม่มี offline sync สำหรับบันทึกทริป

รายการสถานที่ที่อยากไป รายการโปรดกิจกรรม และกิจกรรมส่วนตัวเดิมยังเก็บแยกบัญชีบนโทรศัพท์ ไม่ซิงก์ข้ามเครื่อง การ logout ไม่ลบข้อมูลเหล่านี้ การล้างข้อมูลแอปทำให้ข้อมูลเฉพาะเครื่องหาย

## แจ้งเตือนแยกบัญชี

ต้องเข้าสู่ระบบก่อนตั้งเตือน ทั้งเตือนจริงและทดสอบมี owner ID ใน payload/identifier ดูและยกเลิกเฉพาะบัญชีที่ใช้อยู่ ออกจากระบบหรือ session หมดอายุจะยกเลิกการเตือนของบัญชีเดิมและนำรายการที่แสดงแล้วออก การเปลี่ยนบัญชีไม่เปิดรายละเอียดจาก notification ของบัญชีอื่น

รายการเตือนรุ่นเก่าที่ไม่มีเจ้าของจะถูกล้างระหว่างตรวจ session เพื่อไม่ให้ปะปน เมื่อกลับเข้าสู่ระบบต้องตั้งการเตือนใหม่ ไม่คืนรายการเตือนที่ยกเลิกโดยอัตโนมัติ การยกเลิกนี้ทำเฉพาะเครื่องที่ออกจากระบบ ไม่สั่งยกเลิกโทรศัพท์อีกเครื่อง

## ตรวจบนโทรศัพท์

1. สมัคร → แก้ชื่อ/แนะนำตัว/เลือกรูป → บันทึก → เปิดแอปใหม่แล้วข้อมูลยังอยู่
2. สร้างทริปพร้อมวัน โน้ต รูป และสถานที่ → เปิดอ่าน/แก้ไข → รีสตาร์ต API แล้วข้อมูลยังอยู่
3. สลับบัญชี A/B: โปรไฟล์และทริปไม่ปะปน ลบทริปของ B ไม่กระทบ A
4. ตั้งเตือน 15 วินาทีแล้วออกจากระบบก่อนครบเวลา ต้องไม่มีเตือนเดิม; กลับเข้า A แล้วตั้งใหม่เพื่อทดสอบแตะเปิดรายละเอียด
5. ปิด API ระหว่างบันทึก: เห็น error และข้อมูลที่กรอกยังอยู่ เปิด API แล้วลองใหม่
6. เลือกรูปแล้วกดยกเลิก: รูปเดิมยังอยู่; ทดสอบรูปเกินขนาดและนำรูปออก

ยังเป็น API สำหรับงานเรียนในเครือข่ายที่ไว้ใจได้ ไม่ใช่บริการออนไลน์ production ไม่มี email verification/password reset/HTTPS hosting/rate limiting ใช้บัญชีทดสอบและไม่ใช้รหัสผ่านจริงซ้ำบริการอื่น
